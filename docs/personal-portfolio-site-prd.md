## 2. 背景与问题

### 2.1 问题陈述

个人创作者需要一个可控、加载体验稳定、能同时承载图片与视频的公开作品集。访客应能快速理解创作者的风格和能力、浏览完整项目并发起联系；站主应能不依赖开发人员完成登录、媒体上传、作品编辑、排序和发布。

### 2.2 产品目标

1. 在一个公开入口中展示创作者定位、精选作品、完整项目和联系方式。
2. 支持图片与视频混合项目，保留封面、排序、标题、描述、标签和无障碍文本等内容元数据。
3. 站主登录后能完成从上传到发布的闭环，并能撤回已发布内容。
4. 在移动端和桌面端保持可读、可浏览、可分享的作品展示体验。

### 2.3 成功指标（上线后 30 天）

| 指标 | 目标 | 数据来源 |
| --- | --- | --- |
| 首页到首个项目详情的点击率 | ≥ 25% | `project_card_click` / `page_view` |
| 项目详情页中位浏览深度 | ≥ 60% 资产或停留 ≥ 45 秒 | `asset_view`、`project_engaged` |
| 联系表单提交成功率 | ≥ 95%（已打开表单的会话） | `contact_submit_success` / `contact_submit_start` |
| 首页移动端 LCP | p75 ≤ 2.5 秒（4G 模拟） | RUM / Lighthouse |
| 后台发布成功率 | ≥ 98%（通过校验的发布操作） | `project_publish_success` |
| 上传失败可恢复率 | ≥ 90%（网络中断后重试） | `upload_resume_success` |

> 以上是首版目标值。发布前需要结合实际媒体体积、CDN 和存储成本重新确认。

## 3. 范围与边界

### 3.1 MVP 范围

- 公开首页、作品列表、作品详情、关于、服务/合作、联系、隐私说明、404 页面。
- 图片和视频媒体的上传、预览、排序、封面设置、元数据编辑。
- 站主账号登录、退出、找回密码（若使用邮箱认证服务）。
- 后台仪表盘、项目管理、媒体库、站点资料设置、联系线索查看。
- 项目草稿、已发布、已下线三态；发布前必填校验。
- 响应式布局、键盘可操作、基本 SEO、Open Graph 分享图。

### 3.2 非目标

- 不做公开用户注册、社交关注、评论、点赞或会员体系。
- 不做在线剪辑、复杂调色、AI 生成或批量视频转码工作台。
- 不做多站点、多租户和复杂团队协作；MVP 默认一个站主账号。
- 不承诺原始素材下载、付费售卖或版权交易；若未来需要，单独设计权限和订单系统。

### 3.3 假设、约束与依赖

- 默认只有一个创作者品牌和一个公开站点；账号隔离仍以用户 ID 为所有内容查询条件。
- 媒体文件存储在对象存储，公开访问通过 CDN 或签名 URL；具体供应商可替换。
- 视频转码、缩略图和海报帧由媒体处理服务完成；若暂不接入转码，上传格式需收紧。
- 站主提供品牌名、头像/Logo、简介、社交链接、联系邮箱和默认分享图。
- 合法上传者必须拥有素材的使用权；后台需提供版权与隐私提醒。

### 3.4 已确认技术选型

| 层级 | 选型 | 在本项目中的职责与边界 |
| --- | --- | --- |
| 前端 | React + TypeScript + Tailwind CSS | 实现公开站点、响应式布局、后台管理界面和可访问交互；所有页面和组件使用 TypeScript 类型约束，样式通过 Tailwind CSS 统一管理。 |
| 后端 | Node.js | 提供认证后的业务 API、项目/媒体/线索 CRUD、发布校验、上传凭证和服务端安全逻辑；具体采用 Vercel Functions 或同平台 Node.js 路由由开发阶段确认。 |
| 部署 | Vercel | 承载前端构建产物和 Node.js API；使用 Preview 环境验证 PR，Production 环境关联正式域名。 |
| 数据库与平台服务 | Supabase | 使用 Supabase PostgreSQL 保存业务数据；优先使用 Supabase Auth 管理站主会话、Supabase Storage 管理媒体对象，并对暴露 schema 的表和 Storage 路径启用 RLS/策略。 |
| 代码仓库 | GitHub | 保存源代码、数据库迁移、配置模板和文档；通过 Pull Request 合并，提交 CI 的类型检查、Lint、测试和构建结果。 |

默认系统链路为：浏览器 → Vercel React 应用 → Vercel 上的 Node.js API → Supabase PostgreSQL/Auth/Storage。原始媒体和私有草稿不放入 GitHub；服务端密钥只存放在 Vercel 环境变量，不能进入浏览器端代码。

视频转码和长时间媒体处理不强制在 Vercel 请求生命周期内完成。若 Vercel Functions 的时长或资源限制不满足真实素材，需要接入异步媒体处理服务，并通过 `upload_tasks` 状态回写 Supabase。

## 4. 用户与关键场景

### 4.1 用户角色

| 角色 | 目标 | 权限 |
| --- | --- | --- |
| 访客 | 了解创作者并浏览作品、发起合作 | 读取已发布内容，提交联系表单 |
| 站主 | 管理品牌、作品和线索 | 登录后台，管理本人全部内容 |
| 未来编辑（预留） | 协助整理作品但不能改账号安全 | 仅管理内容，不管理用户和站点密钥 |

### 4.2 关键用户旅程

**访客浏览：** 首页首屏理解定位 → 点击精选作品 → 浏览项目详情中的图片/视频 → 查看关于或服务 → 提交联系表单 → 获得成功反馈。

**站主发布：** 登录 → 创建项目 → 上传媒体 → 等待处理 → 编辑标题、描述、标签、封面和排序 → 预览公开页面 → 发布 → 在公开站点验证。

**站主维护：** 登录 → 查看草稿或已发布项目 → 编辑/下线/复制项目 → 保存 → 重新发布或恢复草稿。

## 5. 信息架构与页面设计

### 5.1 站点结构

```text
公开站点
├── 首页 /
│   ├── Hero / 创作者定位
│   ├── 精选项目
│   ├── 能力与服务摘要
│   ├── 关于摘要
│   └── 联系 CTA
├── 作品 /work
│   ├── 分类/标签筛选
│   └── 项目详情 /work/:slug
├── 关于 /about
├── 服务 /services
├── 联系 /contact
├── 隐私说明 /privacy
└── 404

管理后台 /admin
├── 登录 /admin/login
├── 仪表盘 /admin
├── 项目 /admin/projects
│   ├── 新建 /admin/projects/new
│   └── 编辑 /admin/projects/:id
├── 媒体库 /admin/assets
├── 联系线索 /admin/inquiries
├── 站点设置 /admin/settings
└── 账号安全 /admin/account
```

### 5.2 公开页面板块

#### 首页 `/`

1. **导航栏**：品牌名/Logo、作品、关于、服务、联系；移动端折叠为菜单。
2. **Hero 首屏**：创作者姓名或品牌、定位句、主视觉（图片或静音循环视频）、“查看作品”主按钮、“联系合作”次按钮。
3. **精选项目**：2–6 个项目卡片；卡片显示封面、项目名、年份/类别和媒体类型标识。
4. **能力摘要**：摄影、短片、品牌视觉、幕后制作等，内容由后台配置。
5. **关于摘要**：头像或肖像、简介、所在地/可合作范围、链接到完整关于页。
6. **联系 CTA**：一句明确的合作邀请、邮箱或联系表单入口。
7. **页脚**：版权、社交链接、隐私说明、后台入口不在公开主导航中展示。

#### 作品列表 `/work`

- 支持全部/摄影/视频/其他自定义分类筛选；筛选状态写入 URL，便于分享和返回。
- 项目卡片优先使用封面；无封面时使用首个可展示资产并提示后台补齐。
- 支持按精选、最新或手动排序；MVP 默认手动排序。
- 空状态显示“正在整理作品”或返回全部作品按钮，不显示空白页面。

#### 项目详情 `/work/:slug`

- 顶部显示项目标题、年份、分类、地点/客户（可选）、一句话简介。
- 资产画廊支持图片全屏查看、视频播放、键盘左右切换和移动端滑动。
- 资产按后台顺序渲染；视频显示海报帧、时长和播放控件，不自动播放带声音内容。
- 项目正文可插入分段说明、制作信息、角色/服务和外部链接。
- 底部提供上一个/下一个项目和联系 CTA。
- 分享元数据使用项目封面、标题和摘要；缺失时回退到站点默认分享图。

#### 关于 `/about`

- 头像/肖像、完整介绍、创作方向、工作方式、所在地/可远程范围。
- 可选合作客户/展映/出版列表；不提供无法验证的荣誉字段。
- 社交、邮箱和下载履历/媒体包的链接由后台开关控制。

#### 服务 `/services`

- 按服务类型展示适用场景、交付内容和咨询入口。
- 每个服务可配置标题、说明、示例项目关联和“询价/合作”按钮。
- 若站主不需要服务页，后台可关闭导航和首页摘要，但已有 URL 应返回 404 或重定向到首页。

#### 联系 `/contact`

- 字段：姓名、邮箱、项目类型、预算区间（可选）、期望日期（可选）、需求说明、隐私同意。
- 提交后显示成功状态和预计回复方式；失败时保留已填内容并提供重试。
- 反垃圾：速率限制、基础人机校验或蜜罐字段；不在前端暴露收件服务密钥。

### 5.3 视觉与交互基线

以下是进入 UI 设计时的默认方向，具体色彩和字体可根据创作者作品调整：

- **气质**：编辑型画廊，留白充足，以作品本身作为视觉主角；首版不使用复杂装饰和高密度信息卡片。
- **色彩**：建议使用中性背景（浅色或深色二选一）配高对比文字和一个品牌强调色；所有颜色通过设计令牌管理，便于切换主题。
- **布局**：桌面端使用 12 列栅格和最大内容宽度约 1,280 px；移动端单列或双列画廊，图片不被裁切为无法理解的比例。
- **层级**：导航和 CTA 保持固定语义；项目卡片只显示标题、分类、年份和媒体类型，详细说明留在项目详情页。
- **动效**：仅用于页面进入、画廊切换和视频播放反馈；遵守 `prefers-reduced-motion`，关闭动效后内容和操作不受影响。
- **视频首屏**：任何自动播放视频都必须静音、可暂停，并使用海报帧作为加载失败回退；首屏低带宽时优先展示静态封面。
- **触控与键盘**：可点击区域不小于 44×44 px；全屏画廊支持 Esc 关闭、左右键切换和可见焦点。
- **内容密度**：首页先建立定位和精选作品的节奏，避免在首屏同时塞入完整履历、长段服务说明和多个表单。

### 5.4 登录与后台页面

#### 登录 `/admin/login`

- 邮箱 + 密码；支持显示/隐藏密码、记住设备（由会话策略决定）、退出。
- 错误提示不区分“账号不存在”和“密码错误”，避免泄露账号信息。
- 连续失败触发限速；成功登录后回到原访问页面或后台首页。
- 找回密码链接仅在已接入邮件服务时启用；令牌一次性、短时有效。

#### 仪表盘 `/admin`

- 显示已发布项目数、草稿数、待处理上传、未读联系线索。
- 提供“新建项目”“继续处理草稿”“查看公开站点”快捷入口。
- 失败上传、处理失败和发布校验错误需要有可点击的错误列表。

#### 项目管理 `/admin/projects`

- 列表字段：封面、标题、状态、分类、精选、更新时间、公开链接。
- 支持搜索、状态筛选、批量下线（需要二次确认）和复制项目。
- 删除默认进入回收站或软删除；MVP 至少保留撤销窗口，避免误删。

#### 项目编辑 `/admin/projects/:id`

- 基本信息：标题、Slug、摘要、正文、年份、分类、标签、客户/地点（可选）。
- 媒体编排：上传、拖拽排序、设为封面、删除/替换、设置每项标题和 Alt 文本。
- 发布设置：精选开关、公开日期、SEO 标题/描述、分享图、可见性。
- 操作：保存草稿、预览、发布、下线；未保存离开时提示。
- 发布按钮显示校验结果；缺少封面、标题、可展示资产或必要 Alt 文本时不可发布。

#### 媒体库 `/admin/assets`

- 按图片/视频、项目、处理状态筛选；展示缩略图、文件名、尺寸、时长、上传时间。
- 支持拖拽或文件选择、多选上传、断点续传、失败重试和取消未完成任务。
- 处理完成后生成展示尺寸、缩略图、视频海报帧和媒体元数据。
- 替换资产时保留项目引用关系；已发布页面在新版本处理完成前继续使用旧资产。

#### 站点设置 `/admin/settings`

- 品牌：站点名、Logo/头像、主色、字体偏好（若实现主题系统）。
- 内容：Hero 文案/媒体、关于简介、服务列表、社交链接、联系邮箱、默认分享图。
- 运营：导航显隐、首页精选项目顺序、默认 SEO、分析开关。
- 保存后支持预览；敏感配置（邮件服务密钥、存储密钥）不在普通内容表单中展示。

#### 联系线索 `/admin/inquiries`

- 列表显示姓名、邮箱、项目类型、提交时间、处理状态。
- 支持标记未读/已读、备注、归档；导出功能列为后续需求。
- 站主可点击邮件地址发起回复，但不在站内保存明文回复内容，除非未来明确设计 CRM 模块。

## 6. 核心状态与流程

### 6.1 项目状态机

```text
草稿 --发布校验通过--> 已发布
已发布 --编辑保存--> 已发布（生成新版本或原子更新）
已发布 --下线--> 已下线
已下线 --编辑并发布--> 已发布
草稿/已下线 --删除--> 回收站（可恢复）
```

- 草稿只对登录用户可见；预览使用带权限校验的预览地址。
- 已发布项目必须至少有一个可展示资产、标题、Slug、摘要或正文中的一项、封面和分类。
- 已发布项目编辑期间不应短暂变成空页面；保存采用原子更新，媒体新版本处理完成后再切换引用。

### 6.2 媒体资产状态机

```text
待上传 → 上传中 → 已上传 → 处理中 → 可用
                         └→ 处理失败 → 可重试
上传中 → 已取消
```

- 处理失败显示可读错误和重试入口，不阻塞其他资产。
- 项目发布只允许引用“可用”资产；未处理完的资产在编辑页明确标识。
- 删除项目或替换资产时保留引用检查，避免删除仍被已发布项目使用的文件。

### 6.3 上传流程

1. 前端选择文件并做扩展名、MIME、大小的初步校验。
2. 服务端签发一次性上传凭证，按分片上传；大文件或弱网场景支持重试和续传。
3. 上传完成后服务端校验文件签名、病毒/恶意内容策略和账号归属。
4. 媒体处理服务生成缩略图、展示尺寸、海报帧、时长和宽高元数据。
5. 站主补充标题/Alt 文本并将资产加入项目；项目保存后才建立正式引用。

## 7. 功能需求

优先级：P0 = MVP 必须，P1 = 首次上线建议，P2 = 后续增强。

| ID | 优先级 | 角色 | 需求与验收标准 |
| --- | --- | --- | --- |
| AUTH-001 | P0 | 站主 | 给定有效凭证，登录成功后创建安全会话并进入后台；无效凭证不泄露账号是否存在。 |
| AUTH-002 | P0 | 站主 | 给定已登录会话，访问后台页面返回内容；会话过期后跳转登录并保留回跳地址。 |
| AUTH-003 | P0 | 站主 | 退出后当前会话失效，再次访问后台必须重新认证。 |

## 8. 媒体与内容规则

### 8.1 推荐格式与默认限制

以下是 MVP 的可配置默认值，技术评估阶段需根据存储和转码成本确认：

| 类型 | 推荐输入 | 默认上限 | 展示策略 |

## 10. 非功能需求

### 10.1 性能

- 首页首屏 LCP p75 ≤ 2.5 秒，CLS p75 ≤ 0.1；图片采用懒加载、响应式尺寸和明确宽高。
- 详情页首屏只加载可视区域媒体；视频只预加载海报或元数据，不默认下载整段视频。
- 后台列表首屏 API p95 ≤ 500 ms（不含媒体处理）；大文件上传使用分片，不占用单个请求连接。

### 10.2 安全与隐私

- 密码使用成熟哈希算法存储；全站 HTTPS；Cookie 会话启用 HttpOnly、Secure、SameSite。
- 后台 API 默认拒绝跨账号访问；对象存储桶默认私有，公开资源通过受控 CDN 访问。
- 登录、上传、联系表单和发布接口分别设置速率限制；关键操作写审计日志。
- 不把邮箱、存储密钥、上传凭证和内部错误堆栈返回给公开客户端。
- Supabase 暴露 schema 中的每张业务表必须启用 RLS；策略使用 `TO authenticated`/`TO anon` 和账号归属条件，不使用可被用户编辑的 `user_metadata` 作为授权依据。
- Supabase `service_role` 或 secret key 只在 Node.js 服务端使用；React 客户端使用 publishable/anon key，并通过策略限制数据范围。
- 公开项目读取、后台草稿读取、联系线索读取和媒体 Storage 访问分别定义策略；不能用一个“已登录即可访问全部数据”的通用策略。

### 10.3 可访问性与兼容性

- 目标 WCAG 2.2 AA；键盘可操作，焦点顺序合理，动态状态有文本提示。
- 支持最近两个主流版本的 Chrome、Safari、Edge、Firefox；移动端覆盖 iOS Safari 和 Android Chrome。
- 视频提供可见控件；若发布有对白内容的视频，P1 支持字幕轨或文本说明。

### 10.4 可靠性与可运维性

- 上传、转码、发布采用可重试任务；任务状态可观测并带错误码。
- 数据库、对象存储和站点设置需有定期备份策略；恢复演练至少在上线前完成一次。
- 监控公开 5xx、登录失败率、上传失败率、媒体处理积压和联系表单失败率。

### 10.5 技术实现约束

- **TECH-001（前端）**：公开站点和后台必须使用 React + TypeScript；新增组件、页面数据和 API 响应不得绕过 TypeScript 类型检查。
- **TECH-002（样式）**：页面样式统一使用 Tailwind CSS 和项目设计令牌；不得在单个页面引入相互冲突的临时全局样式。
- **TECH-003（后端）**：业务 API 使用 Node.js；敏感操作（发布、删除、签发上传凭证、读取私有线索）必须经过服务端鉴权和输入校验。
- **TECH-004（Supabase）**：所有暴露 schema 的业务表启用 RLS；策略按 `owner_id`/站点归属限制读写，公开读取只允许已发布内容。更新策略同时定义 `USING` 与 `WITH CHECK`，避免通过更新改写归属。
- **TECH-005（密钥）**：浏览器端只能使用 Supabase publishable key（或兼容的 anon key）；`service_role`/secret key 只允许在 Node.js 服务端使用，禁止出现在 `NEXT_PUBLIC_*` 或其他客户端变量中。
- **TECH-006（Storage）**：原始媒体和草稿资产默认私有；上传凭证短时、单次、限定账号路径。若启用 Storage upsert，必须同时配置 INSERT、SELECT、UPDATE 权限并覆盖替换场景测试。
- **TECH-007（部署）**：生产部署使用 Vercel，PR 使用 Preview；正式和预览环境分别配置 Supabase 项目/凭证，不能用开发数据库承载生产数据。
- **TECH-008（仓库）**：GitHub 必须提交 lockfile、Supabase 迁移和 `.env.example`（只含变量名）；真实密钥、媒体文件和导出的生产数据不得提交。
- **TECH-009（质量门槛）**：合并前至少通过 TypeScript 类型检查、Lint、自动化测试和生产构建；部署后验证公开首页、登录、项目发布和媒体上传主链路。

## 12. 异常与边界

| 场景 | 系统行为 | 用户反馈 |
| --- | --- | --- |
| 未登录访问后台 | 返回 401 并跳登录 | 提示“请先登录”，保留回跳地址 |
| 会话过期时保存 | 拒绝写入并返回 401 | 保存草稿前提示重新登录，不丢失本地未提交内容（若已实现） |
| 文件格式或大小超限 | 上传前后均拒绝 | 指明支持格式和上限，其他文件继续上传 |
| 网络中断 | 保留已完成分片 | 显示暂停/重试，恢复后继续，不重复计数 |
| 媒体处理失败 | 资产标记失败，项目仍可保存草稿 | 显示错误码和重试入口 |
| 重复上传同一文件 | 可按哈希提示已有资产 | 允许复用或明确选择重新上传 |
| 发布时资产被删除 | 发布事务失败 | 指向缺失资产并阻止公开 |
| 公开项目保存失败 | 不切换新版本 | 公开页继续展示旧版本，后台提示重试 |
| 联系服务不可用 | 不丢弃表单内容 | 显示失败并提供邮箱备用方式 |
| 无项目/无媒体 | 返回可读空状态 | 首页与列表提供回到首页或联系入口 |
| 移动端低带宽 | 延迟加载、优先缩略图 | 用户可看到加载状态和重试按钮 |
| 误删项目/资产 | 软删除或引用保护 | 需要确认，支持恢复或明确不可恢复提示 |

## 13. 测试与验收矩阵

### 13.1 自动化测试

- 单元测试：状态机、发布校验、Slug 唯一性、权限判断、文件类型/大小校验。
- API 集成测试：登录/退出、项目 CRUD、媒体任务重试、联系表单、账号隔离。
- E2E 测试：访客从首页浏览到联系提交；站主从登录、上传、编辑、预览、发布到下线。
- 可访问性检查：自动扫描 + 键盘回归；重点页面无严重级别问题。

### 13.2 原生运行测试

- 在本地或预发布环境真实启动前后端和媒体处理任务，使用至少一张图片、一个短视频和一个超限文件验证完整链路。
- 模拟网络中断后恢复上传，确认分片续传且无重复引用。
- 在移动端 Safari、Android Chrome、桌面 Chrome/Edge/Firefox 验证首屏、画廊、视频和后台表单。

### 13.3 人工验收清单

- 站主能在不读代码的情况下完成“新建项目 → 上传 → 排序 → 设封面 → 预览 → 发布”。
- 访客能在 10 秒内理解创作者是谁、作品在哪里、如何联系。
- 公开项目在分享链接预览中显示正确封面、标题和描述。
- 退出账号后无法通过历史后台 URL 或公开预览 URL 读取草稿。
- 错误、空状态、弱网和媒体处理失败均有可执行的下一步提示。

## 14. 发布计划与回滚

### 阶段

1. **基础骨架**：公开路由、响应式布局、数据模型、登录和权限中间件。
2. **内容闭环**：项目 CRUD、媒体上传/处理、预览、发布/下线。
3. **公开体验**：作品筛选、画廊/视频播放、SEO、联系表单、埋点。
4. **预发布验证**：导入真实样例、性能测试、备份恢复和安全检查。
5. **小范围上线**：先由站主验证公开 URL、上传和联系线索，再开放正式域名。

### 14.1 交付与部署约定

- GitHub `main`（或项目约定的生产分支）作为 Vercel Production 部署来源；Pull Request 自动创建 Vercel Preview，供视觉和功能验收。
- Vercel 环境变量按 Development、Preview、Production 分开配置：Supabase URL 和 publishable/anon key 可按客户端需要暴露，`service_role`/secret key 只配置在服务端运行环境。
- Supabase 数据库迁移、RLS 策略和 Storage 策略以版本化文件提交到 GitHub；生产环境不通过手工改表完成正式变更。
- 部署前必须验证 React 构建、TypeScript、Tailwind CSS 产物和 Node.js API 均能在 Vercel Preview 运行；部署后执行首页、登录、草稿保存、媒体上传和发布冒烟测试。
- Vercel Functions 不承担不可控时长的转码任务；媒体处理若超出执行限制，改用异步任务服务并以 Supabase `upload_tasks` 状态驱动前端进度。

### 回滚条件

- 发布接口错误率持续 > 2%；
- 上传或媒体处理失败率 > 10%；
- 公开页出现错误媒体、账号越权或联系线索丢失；
- 性能指标连续 15 分钟超过阈值。

回滚优先恢复上一版应用和内容版本；对象存储文件不直接删除，待确认引用关系后再清理。

## 16. 风险与开放问题

| 问题 | 影响 | 建议决策 |
| --- | --- | --- |
| 是否需要多位编辑 | 影响角色、邀请、审计和账号隔离 | MVP 仅站主；确认后再启用编辑角色 |
| 视频最大体积、时长和码率 | 直接影响存储、转码和加载成本 | 以真实素材样本压测后确定默认上限 |
| 是否允许公开原图/原视频下载 | 影响版权、带宽和签名 URL | MVP 默认不提供下载，后续按项目开关设计 |
| 是否需要自定义域名 | 影响部署、证书和站点设置 | 首版使用单一域名，验证需求后再做绑定 |
| 联系线索保存多久 | 影响隐私策略和数据库清理 | 上线前由站主确定保留期限并写入隐私说明 |
| 是否接入统计分析 | 影响同意机制和地区合规 | 默认关闭非必要追踪，确认地区和工具后开启 |
| 是否需要多语言 | 影响内容模型、SEO 和翻译流程 | MVP 中文或单语言；有明确受众后再扩展 |
| 视频转码部署在哪里 | 影响 Vercel 执行时长、队列和成本 | 先用短视频验证；超出限制时接入异步媒体处理服务 |

## 17. 推荐的首版菜单与页面优先级

**首版必须上线：** 首页、作品列表、项目详情、关于、联系、登录、后台仪表盘、项目编辑、媒体上传、站点设置、隐私说明、404。

**首版可延后：** 服务独立页、联系线索导出、定时发布、多编辑协作、字幕轨、原始素材下载、博客/日志、收藏夹、访问密码项目。

**建议首页视觉重点：** 用一个强识别度的首屏视觉建立风格，用精选项目证明能力，用项目详情展示完整叙事，用联系 CTA 结束路径。后台则以“项目 + 媒体 + 发布校验”作为最短操作链，避免把内容管理拆散到多个孤立入口。
